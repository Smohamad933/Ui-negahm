# راهنمای نصب — نگاه مدیا (PHP خالص، بدون فریم‌ورک)

این نسخه از سایت با **PHP خام** نوشته شده: بدون Composer، بدون `vendor/`،
بدون `artisan`، بدون فایل `.env` و بدون نیاز به ماژول URL Rewrite در IIS.
تمام صفحات با آدرس‌های querystring کار می‌کنند (مثل
`client.php?slug=...`)، پس هیچ نوع rewrite rule لازم نیست.

نصب یعنی: **کل این پوشه را آپلود کنید و همین‌طوری کار می‌کند.** هیچ
دستور خط‌فرمانی، migrate، seed یا build لازم نیست — دیتابیس
(`data/app.sqlite`) از قبل ساخته و با محتوای واقعی پر شده است.

---

## ۱) پیش‌نیاز سرور

- IIS با PHP نصب‌شده از طریق **FastCGI** (نسخه‌ی ۸٫۱ به بالا پیشنهاد می‌شود).
- اکستنشن‌های PHP فعال: `pdo_sqlite` و `sqlite3` (این دو معمولاً به‌صورت
  پیش‌فرض در اکثر نصب‌های PHP روی ویندوز فعال هستند؛ اگر سایت خطای
  «فایل دیتابیس پیدا نشد» یا خطای مربوط به PDO داد، در `php.ini` این دو خط
  را از حالت کامنت خارج کنید:
  ```ini
  extension=pdo_sqlite
  extension=sqlite3
  ```
  و سپس IIS/FastCGI را ری‌استارت کنید.)

نیازی به نصب Composer یا اجرای هیچ دستوری نیست.

---

## ۲) آپلود فایل‌ها

۱. کل محتوای این پوشه (`php-app/` بعد از استخراج از زیپ) را داخل
   ریشه‌ی سایت خود در IIS کپی کنید (همان پوشه‌ای که `index.php` در آن است).

۲. مطمئن شوید هندلر PHP برای پسوند `.php` روی این پوشه فعال است (این
   بخش تنظیمات عمومی سرور شماست و ربطی به این پروژه ندارد).

۳. دسترسی **نوشتن (Write)** برای کاربر IIS (معمولاً `IIS_IUSRS` یا
   `IUSR`) روی این دو پوشه را فعال کنید:
   - `data/`  → چون فایل دیتابیس SQLite داخل آن است و برنامه باید
     بتواند در آن بنویسد.
   - `uploads/` (و زیرپوشه‌های `uploads/images` و `uploads/fonts`) →
     چون فایل‌های آپلودی (لوگو، عکس، ویدئو، فونت سفارشی) داخل آن ذخیره
     می‌شوند.

   در File Explorer: روی پوشه راست‌کلیک → Properties → Security → کاربر
   IIS را اضافه و دسترسی Modify/Write بدهید.

۴. همین! به آدرس دامنه‌ی خود بروید — سایت باید مستقیماً کار کند.

## ۴) اگر سایت را داخل یک زیرپوشه نصب می‌کنید

اگر آدرس سایت شما مثلاً `example.com/negahm/` است (نه مستقیم روی ریشه‌ی
دامنه)، فایل `config.php` را باز کنید و این خط را:

```php
define('BASE_PATH', '');
```

به این تغییر دهید:

```php
define('BASE_PATH', '/negahm');
```

برای نصب مستقیم روی ریشه‌ی دامنه یا یک ساب‌دامنه‌ی اختصاصی، مقدار
پیش‌فرض (`''`) را دست نزنید.

---

## ۵) دیتابیس و فایل‌های آپلودی — نکات پشتیبان‌گیری

- کل دیتابیس سایت (کارفرمایان، دسته‌بندی‌ها، نمونه‌کارها، تنظیمات، پیام‌ها)
  در یک فایل ساده است: `data/app.sqlite`.
- فایل‌های آپلودی (لوگو، تصاویر، ویدئوها، فونت‌های سفارشی) در پوشه‌ی
  `uploads/` ذخیره می‌شوند.
- برای پشتیبان‌گیری کامل، کافی است این دو مسیر را به‌صورت دوره‌ای کپی
  بگیرید: `data/app.sqlite` و `uploads/`.
- این دو مسیر همچنین در فایل `web.config` همراه پوشه‌های `install/`،
  `lib/` و `partials/` از دسترسی مستقیم مرورگر مسدود شده‌اند (کسی
  نمی‌تواند مستقیماً فایل `app.sqlite` را دانلود کند).

## ۶) اگر خواستید دیتابیس را از صفر بسازید (اختیاری، فقط برای توسعه‌دهنده)

فایل `data/app.sqlite` از قبل ساخته و با ۳۴ کارفرمای نمونه پر شده است؛
نیازی به این مرحله نیست. اما اگر روی سروری با دسترسی PHP CLI هستید و
خواستید دیتابیس را کاملاً از نو (خالی از تغییرات دستی که در پنل دادید)
بسازید:

```
php install/seed.php
```

توجه: این دستور فایل `data/app.sqlite` فعلی را **پاک و بازسازی می‌کند**
(تمام تغییراتی که از داخل پنل مدیریت داده‌اید از بین می‌رود و به حالت
اولیه‌ی نمونه برمی‌گردد). فقط در صورت نیاز واقعی اجرا کنید.

## ۷) عیب‌یابی سریع

| مشکل | راه‌حل |
|---|---|
| صفحه‌ی «فایل دیتابیس پیدا نشد» | مطمئن شوید پوشه‌ی `data/` را کامل آپلود کرده‌اید (شامل فایل `app.sqlite`) و پسوند `.sqlite` توسط آنتی‌ویروس/سرور حذف نشده. |
| خطای مربوط به PDO یا SQLite | اکستنشن‌های `pdo_sqlite` و `sqlite3` را در `php.ini` فعال کنید (بخش ۱ همین فایل). |
| آپلود عکس/فونت با خطا مواجه می‌شود | دسترسی نوشتن پوشه‌ی `uploads/` برای کاربر IIS را بررسی کنید (بخش ۲). |
| رمز ورود پنل را فراموش کردید | با دسترسی به فایل دیتابیس (مثلاً با یک ابزار SQLite Browser)، ستون `password_hash` جدول `admin_users` را با هش رمز جدید (تولید‌شده با تابع PHP `password_hash()`) جایگزین کنید. |
| صفحات RTL/فارسی درست نمایش داده نمی‌شوند | مطمئن شوید پوشه‌ی `fonts/` (فونت Vazirmatn) و `css/app.css` به‌طور کامل آپلود شده‌اند. |
| باز کردن سایت باعث دانلود/نمایش سورس فایل‌های `.php` می‌شود (به‌جای اجرای آن‌ها) | یعنی IIS اصلاً هندلر FastCGI برای PHP ندارد — به بخش ۸ مراجعه کنید. |
| خطای «403 - Forbidden» یا «500.19 - Internal Server Error» بعد از تنظیم `web.config` | معمولاً یعنی یک Handler تکراری برای `*.php` تعریف شده — به بخش ۸ مراجعه کنید. |

هیچ مرحله‌ی دیگری لازم نیست — این پروژه به‌صورت عمدی بدون هیچ مرحله‌ی
build یا نصب اضافه طراحی شده است.

---

## ۸) خطای 403 / 500.19 یا اجرا نشدن PHP — راهنمای هندلر FastCGI

فایل `web.config` این پروژه **عمداً** هیچ `<handlers>` برای PHP اضافه
نمی‌کند، چون اضافه‌کردن یک Handler تکراری برای `*.php` وقتی PHP از قبل
روی سرور (مثلاً از طریق **PHP Manager for IIS** یا تنظیمات سطح سرور)
ثبت شده، با آن تداخل می‌کند و باعث خطای «403 - Forbidden» یا «500.19»
می‌شود — این دقیقاً همان مشکلی است که یک‌بار در نسخه‌ی قبلی این پروژه
پیش آمد و رفع شد، پس این‌جا از ابتدا کنار گذاشته شده.

**قبل از هر تغییری در `web.config` این را بررسی کنید:** آیا وقتی به
آدرس سایت می‌روید، PHP اصلاً اجرا می‌شود؟ (یعنی صفحه‌ی سایت را می‌بینید،
نه اینکه مرورگر سورس `index.php` را به‌عنوان دانلود پیشنهاد بدهد یا
صفحه‌ی خالی/لیست پوشه نشان بدهد.)

- **اگر PHP اجرا می‌شود ولی فقط صفحه‌ی اول (`/`) کار نمی‌کند:** به احتمال
  زیاد `index.php` در Default Document سرور شما ثبت نبوده — نسخه‌ی
  فعلی `web.config` این را با بخش `<defaultDocument>` رفع کرده، پس اگر
  همچنان مشکل دارید مطمئن شوید همین فایل `web.config` واقعاً آپلود شده
  و در ریشه‌ی سایت (کنار `index.php`) قرار دارد.

- **اگر PHP اصلاً اجرا نمی‌شود (سورس فایل دانلود می‌شود یا خطای 404 برای
  فایل‌های `.php` می‌گیرید):** یعنی هیچ Handler‌ای برای `*.php` در سطح
  سایت یا سرور IIS شما تعریف نشده. دو راه دارید:

  **راه ۱ (توصیه‌شده): از PHP Manager for IIS استفاده کنید.** این ابزار
  رایگان مایکروسافت به‌صورت خودکار PHP را به‌عنوان FastCGI Handler به
  IIS معرفی می‌کند و نیازی به تغییر `web.config` نیست.

  **راه ۲: افزودن دستی Handler در `web.config`.** اگر PHP را کاملاً
  دستی نصب کرده‌اید (بدون هیچ ابزار مدیریتی) و مطمئن هستید هیچ Handler
  دیگری برای `*.php` در IIS Manager (نه در سطح سایت و نه در سطح سرور)
  وجود ندارد، بخش کامنت‌شده‌ی زیر عنوان «PHP FastCGI Handler» را در
  `web.config` پیدا کنید و کامنت آن را بردارید:

  ```xml
  <handlers>
    <add name="PHP_via_FastCGI" path="*.php" verb="*"
         modules="FastCgiModule"
         scriptProcessor="C:\php\php-cgi.exe"
         resourceType="Either" />
  </handlers>
  ```

  حتماً مسیر `scriptProcessor` را با مسیر واقعی `php-cgi.exe` روی سرور
  خودتان جایگزین کنید (مسیر بالا فقط یک نمونه است).

  **⚠️ اگر بعد از این کار خطای 403 یا 500.19 گرفتید**، یعنی یک Handler
  دیگر برای `*.php` از قبل در جایی (سطح سایت یا سرور) وجود داشته و این
  بخش با آن تداخل کرده — در این حالت بخش `<handlers>` را دوباره کامنت
  کنید/حذف کنید و به‌جایش از **راه ۱** (PHP Manager for IIS) استفاده
  کنید یا با پشتیبانی هاست خود تماس بگیرید تا Handler موجود روی سرور
  را برایتان مشخص کنند.

  بعد از هر تغییر در Handler، **Application Pool سایت را Recycle
  کنید** (یا IIS را Restart کنید) تا تغییرات اعمال شود.
